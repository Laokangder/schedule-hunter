## 零、2026-10-14 Android 提醒与通知监听复核

### 0.1 当前结论

当前必须区分四类相关逻辑：

- **开始提醒**：后端每 30 秒扫描一次 `start_time`，按 `30/10/5/0` 分钟档位发送 `REMINDER` WebSocket 消息。
- **Android 本地到点通知**：客户端已经按 `reminder_policy` 向系统注册通知，用于后台、息屏和断网提醒；代码已完成，尚待真机矩阵验收。
- **其他 App 系统通知监听**：第一版 `NotificationListenerService` 已接线，可在用户授予通知使用权后捕获具有时间线索的通知并进入候选解析；尚待真机兼容验收。
- **任务过期**：后端每 30 秒扫描一次 `end_time`，将 `scheduled/pending` 更新为 `expired`，再广播 `TASK_UPDATED`；前端另有每秒一次的本地列表过期显示。

WebSocket 只负责前台状态和跨端刷新，不再作为 Android 后台提醒的唯一保证。现有“灵动岛”是 WebView 页面内组件；App 后台已有系统监听、本地排队、服务端解析和标准高优先级候选横幅，但尚未实现跨应用悬浮展示。

### 0.3 Android 本地到点通知：代码完成，待真机验收

`@capacitor/local-notifications@8.3.1` 已加入依赖并完成业务接线与原生同步。创建日程会注册提醒，删除、完成和过期会取消，恢复或改期可重建；启动时会校准并清理重复待通知，Android 原生插件负责手机重启恢复。

目标链路：

```text
任务创建/改期成功
  → 生成稳定的本地通知 ID
  → 按 reminder_policy 注册 Android 本地通知
  → Android 在后台、息屏或离线时到点展示
  → 点击通知打开对应任务详情
```

仍需补齐：

1. 后台、息屏、断网、进程回收、重启和权限拒绝场景的真机测试。
2. vivo 省电限制、精确提醒拒绝时的延迟表现和强制停止后的恢复验证。
3. 后端任务编辑/改期接口和用户可见编辑流程，以实际调用通知重建能力。
4. 本地系统通知与 WebSocket 前台提示的体验去重验证。

### 0.4 已接线、待真机验收的 P0：Android 系统通知监听

当前 Android 工程已有 `ScheduleNotificationListenerService`、`BIND_NOTIFICATION_LISTENER_SERVICE` 注册、通知使用权设置入口、原生事件 Bridge、隐私过滤和最多 100 条的本地捕获队列。原生层还会排除自身/常驻/系统通知，以时间表达式预筛，并用通知 key 与内容指纹抑制短时间重复更新。

前台事件进入统一解析流程；后台由原生线程调用同一后端接口并缓存成功响应，再发送标准高优先级通知。两条路径都只生成候选或冲突状态，不直接创建日程。仍需补齐按来源 App 开关、清空缓存、通知撤销，并完成不同系统与应用通知格式的真机回归；厂商私有系统灵动岛不作为跨设备承诺。

### 1.3 与历史结论的冲突

- 2026-05-05 文档中的“LLM 时间提取已达成”只适用于当时成功调用模型的场景，不能代表当前降级解析能力。
- “过期任务自动标记已完成”与本轮后端实测不一致。前端可以用时间戳显示过期，但后端新建的 `scheduled` 任务不会被只扫描 `pending` 的逻辑更新。
- “冲突检测接口已实现”应调整为“代码存在但合法 API 请求不可用”。
- “API 响应结构一致”与本轮实测不一致，Pydantic 响应模型会裁掉服务层生成的多个字段。
- “APK 打包与局域网真机通信”依赖固定地址 `192.168.2.8`，不能视为可移植的构建或部署能力。

```javascript
function isExpired(task) {
  if (task.status === 'expired') return true
  if (!task.start_time) return false
  const now = Date.now()
  const startTime = new Date(task.start_time).getTime()
  const endTime = task.end_time ? new Date(task.end_time).getTime() : startTime + 3600000
  return endTime < now
}
```

```javascript
_schedule_reminder(task) {
  if (!task?.start_time) return
  const now = Date.now()
  const start = new Date(task.start_time).getTime()
  const diff = start - now
  if (diff <= 0) {
    this.active_task = task
    this.island_state = 'reminder'
  } else if (diff <= this.reminder_threshold) {
    this.active_task = task
    this.island_state = 'tracking'
  } else {
    this.active_task = task
    this.island_state = 'tracking'
  }
}
```
